为什么偏偏是现在

旧系统失效 · DevOps 工具 Garnix (Nix CI) 宣布停服：专业构建用户面临迁移真空

Nix 专属 CI 服务 Garnix 宣布关闭，HN + Lobsters 双平台发酵。Nix 生态的 CI/CD 需求高度专业化，主流 CI 提供商（GitHub Actions、CircleCI）对 Nix 支持极差，用户付费意愿强但无处可去。

为什么偏偏是现在

Nix/NixOS 生态近两年高速增长（GitHub Stars 持续上涨），但专业基础设施工具严重滞后。Garnix 是少数专注 Nix 的 CI 服务之一，其关闭暴露了整个生态的基础设施脆弱性。用户现在处于强制迁移状态。

旧系统失效

  • Nix 的确定性构建特性要求 CI 环境深度理解 Nix store、binary cache、flake.lock
  • GitHub Actions 虽可通过插件支持 Nix，但速度慢 10x+，无法利用 Nix 增量缓存
  • Garnix 停服意味着用户要么降级回慢速方案，要么寻找根本不存在的替代品

创业方向

① Nix-Native CI/CD 服务：从底层支持 Nix binary cache sharing、Nix flake evaluation、远程构建。Garnix 的关闭留下了明确的用户群等待迁移
② Universal Build Cache：不仅支持 Nix，还支持 Bazel/Buck，统一分布式缓存基础设施
③ Nix 迁移顾问服务：帮助中型团队将 Nix 工作流迁移到现有 CI 平台（短期服务）

新能力出现 · AI 安全治理 Protestware for Coding Agents：开发者用代码抵制 AI 自主执行，揭示 Agent 治理真空

Lobsters（65分）：开发者开始编写「Protestware」——当代码由 AI Agent 自主执行时会以不同方式（降级、告警、拒绝）响应。这是对 AI Agent 无审计执行权限的底层抵制，也揭示了 AI agent 行为验证工具市场的空白。

为什么偏偏是现在

Claude Code、Devin、SWE-agent 等 AI Coding Agent 正在从「建议」转向「自主执行」——直接写代码、提交 PR、修改配置文件。企业风险暴露快速上升，但现有代码审查流程完全没有针对「AI 执行路径」的特殊处理。Protestware 的出现标志着开发者已从接受转向主动防御。

痛点列表

  • 无法判断一段代码修改是人写的还是 AI Agent 写的
  • AI Agent 执行权限过大，可在无人审查时修改生产配置
  • Protestware 说明开发者用「以暴制暴」方式应对——本质是正式治理工具缺席
  • 企业合规要求代码变更留审计轨迹，AI Agent 执行破坏此假设

创业方向

① AI Agent 行为审计平台：记录 AI Agent 的每次文件读写/命令执行/API 调用，支持回滚和事后审查
② 代码变更溯源系统：Git 提交自动标注「人工编写 vs AI 辅助 vs AI 自主执行」，满足企业合规需求
③ AI Agent 权限沙箱：类似 Docker 的容器化执行环境，限制 AI Agent 的文件系统和网络访问范围

为什么偏偏是现在

GitHub（微软旗下）与其最大客户 Microsoft 的利益冲突在此案例中赤裸裸暴露。同时微软发布了一个「永久性」GitHub 封禁，而非临时处置。安全研究界此前对 GitHub 的中立性有幻想，此案终结了这一幻想。

问题本质

  • 安全研究员 PoC 代码需要可靠托管和版本控制，与普通代码无区别
  • GitHub 作为私人平台有权封禁任何人，但安全研究生态过度依赖此单一渠道
  • 现有替代品（Codeberg、SourceHut、Gitea）缺乏安全研究专属功能（负责任披露流程、CVE 联动、协调通知）

创业方向

① 安全研究专属代码托管平台：Git + 内置负责任披露工作流，明确平台政策保护安全研究者（可参考 SourceHut 模式）
② 去中心化漏洞披露协调工具：CVE 申请、厂商通知、公开发布的结构化流程管理，减少对平台审查的依赖
③ 安全研究者数字身份工具：基于密码学的研究者身份证明，当账号被平台封禁时可快速迁移声誉
